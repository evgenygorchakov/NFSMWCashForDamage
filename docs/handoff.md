### Отличия реализации от плана ниже
- `VerifyBuild` возвращает `BuildCheck`: `NotV13` (база или timestamp) — сразу фатальная ошибка
  без повторов; `CodeDiffers` — повтор до ~5 с, затем фатальная ошибка со списком отличий.
- `Tracker::ObjectGone()` вызывается, когда игрок найден и `pursuit==0`, и при выходе из
  RACING. Если после этого тот же адрес погони вернулся с **меньшим** значением, это новая
  погоня (аллокатор отдал тот же адрес) — считается с нуля. С тем же или большим значением —
  продолжение, платится только разница (двойной оплаты нет). Основание: `AIVehicle::mPursuit`
  ставится в `OnOwnerAttached` и обнуляется в `OnOwnerDetached` (декомпиляция, `AIVehicle.cpp:643`),
  то есть у живой погони он пропадать не должен.
- `Tracker::kMaxDelta = 10 000 000`: скачок больше считается ошибкой чтения, берётся новая база.
- После каждого возврата в заезд/карьеру статус игрока и строка «Игрок: ... деньги $N»
  пишутся заново (для сверки денег с меню).
- `ReadCostToState` после вызова перечитывает `[IVehicleAI+0x70]` и vtable погони. Если погоня
  пропала во время чтения, опрос пропускается (в лог — один раз на погоню).

                      InterlockedCompareExchange-прибавление к int32

src/Tracker.h/.cpp    чистая логика без WinAPI (Tracker + Payout), покрыть тестом
src/Config.h/.cpp     свой парсер INI (секции игнорируем, ; и # — комментарии в любом месте строки,

                      запятая = точка)

Функции с `__try` не должны содержать C++-объектов с деструкторами (C2712), поэтому SEH держим
в маленьких функциях `Memory.cpp`. SDK-заголовки не подключаем: работаем по проверенным смещениям.

### Чтение состояния (каждый тик)
1. `[0x925E90] == 6` (RACING), иначе пропуск. Смену состояния пишем в лог.
2. `GRaceStatus = [0x91E000]` не null и `[GRaceStatus+0x1964] == 2` (карьера), иначе пропуск.
3. Цепочка к игроку (`docs/research.md`, п. 4). На каждом шаге: указатель правдоподобен
   (≥0x10000, <0x80000000, выровнен на 4), чтение под SEH, vtable совпадает:
   `[0x92D884]≠0` → `iplayer=[[0x92D87C]]` (vt `0x8B0B10`) → `simable=[iplayer-8]` →
   `com=[simable+4]` → пары `{handle,iface}` по 8 байт в `[com+4]..[com+8]` (не больше ~64) →
   IVehicleAI (handle `0x403700`, vt `0x8929F0`), IPerpetrator (handle `0x4037E0`, vt `0x892988`),
   проверка `iperp - ivehai == 0x70C` → `pursuit=[ivehai+0x70]` (если не 0, то vt `0x892770`).
4. `PlayerDamage = (int32)[iperp+0x20]`.
   `CostToState = CalcTotalCostToState(pursuit)` — вызов `0x40AA00` (`__thiscall`, без побочных
   эффектов, только читает поля) под SEH. Без погони — 0.
5. Деньги: `[[0x91CF90]+0x10]+0xB4`, `int32`.

### Логика начисления
- `Tracker(object, value)`:
  - **CostToState**: объект = указатель погони. Сэмплируем только при `pursuit≠0`.
    Последняя погоня запоминается и на время `pursuit==0`, чтобы при кратком пропадании
    не начислить второй раз. Новая (другой указатель) погоня считается **с нуля**, как HUD.
    Та же погоня и значение выросло — начисляем разницу. Значение упало (адрес занят новой
    погоней) — новая база, без начисления (правило ТЗ).
  - **PlayerDamage**: объект = указатель нарушителя. Новый объект — база = текущее значение,
    без начисления. Рост — начисляем. Падение — новая база.
- `Payout`: `carry += delta*Multiplier`; начисляем `floor(carry+1e-6)`, остаток переносим
  (дробные множители не теряют деньги).
- Если запись денег не удалась, сумма остаётся в `pending` и записывается со следующего тика.
  Насыщение на `INT32_MAX` с записью в лог.
- Состояние Tracker при уходе в меню не сбрасываем: новые объекты после загрузки сами дадут
  «новый объект».

### Что пишет лог
- Старт: версия плагина, путь exe, итоговые настройки, предупреждения парсера INI.
- Результат VerifyBuild: при несовпадении — какой участок, ожидалось/получено.
- Смена GameFlowState (по имени), смена «карьера / не карьера (контекст N)».
- Смена статуса поиска игрока. При первом «найден» — указатели и **текущие деньги**
  (для сверки с меню).
- «Погоня началась» / «Погоня закончилась: итог N, урон от игрока M, начислено $K».
- **Каждое начисление**: `+$X: CostToState A -> B (×mult) | деньги C -> D`.
- Ограничение на число строк о смене статуса (~200 за сессию), чтобы лог не разрастался при «дребезге».

### Конфликты с установленными плагинами (проверено поиском констант в .asi)
Ни один из 7 плагинов в `SCRIPTS` не содержит наших адресов **кода**. Ссылаются только на
глобальные переменные (вероятно, читают их): `0x925E90` — XenonEffects, ExtraOptions,
FEShadows, ZPatchMW; `0x91E000`, `0x91CF90` — ExtraOptions. Сигнатуры в памяти должны совпасть.
Если не совпадут, VerifyBuild пишет в лог, какой участок отличается: значит, его переписал
другой плагин.
